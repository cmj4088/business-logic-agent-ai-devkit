## 门禁投票规则

### 普通模式
- 每个门禁关联 2-4 个审批角色
- 投票选项：通过 / 驳回 / 需要修改
- 所有角色通过 → 门禁通过
- 任一角色驳回 → 门禁不通过

### 单人模式（MVP 默认）
- 所有投票自动标记为"通过"
- UI 标注："自动通过，未经人工实质审查"
- 审计日志记录：`auto_approved_due_to_single_user_mode`
- 门禁通过但产出物仍可被用户手动驳回

---

## 审核升级路径

```
门禁不通过
  ├── 修改后重新提交（默认）
  ├── 升级到更高级别审批（需配置）
  ├── 带着遗留问题前进（有条件通过，下一门禁检查）
  └── 回退到上一阶段修复
```

## 禁止事项

1. **禁止在单人模式下阻塞流程**（必须自动通过）
2. **禁止投票结果不可追溯**（每次投票必须记录审计日志）
3. **禁止遗留问题被静默忽略**（下一门禁必须检查）
4. **禁止跳过驳回后的修改环节**
5. **禁止审核升级无超时机制**（默认 72 小时，超时自动升级）
6. **禁止在审核页面显示其他用户的待审核项**（MVP 单人模式，但预留）
